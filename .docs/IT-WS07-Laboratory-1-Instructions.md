# LABORATORY ACTIVITY 1 – CAPSTONE MOBILE PROTOTYPE

## Unit 1: Mobile Application Foundation Review

**Type:** Take-Home Laboratory – Group Activity  
**Grouping:** Existing Capstone Project Group  
**Submission, Presentation & Checking:** Please refer to the official class announcement for the submission schedule.

## Objective

Develop an **Ionic-Angular** mobile prototype based on selected features/modules of your existing capstone project and apply the concepts discussed in Unit 1.

## Instructions

1. Select **at least two (2) features/modules** from your existing capstone project.
2. Develop their mobile prototype using **Ionic-Angular**.
3. The prototype does not need to be fully functional or connected to your actual database, API, or backend. Static/sample data may be used.
4. Your implementation must demonstrate:
   - **Service** – provide data or functionality to the application.
   - **Routing / routerLink** – working and logical navigation between pages.
   - **Reusable Components** – component/s that have a meaningful reusable purpose.
   - **Angular Binding** – appropriate use of interpolation, property binding, event binding, and/or form binding.
   - **@for and @if** – meaningful use for repeated and conditional content.
   - **UI/UX** – interface should be appropriately designed/adapted for mobile use.
5. `FormsModule` / `ngModel` may be used when appropriate but is not required.
6. **Do not add features or code solely to satisfy a requirement.** Each implementation should have a logical purpose within your prototype.

## Presentation & Checking

Each group will demonstrate the prototype during checking. Any member may be asked to demonstrate, locate, or explain any part of the implementation.

Individual understanding will be graded separately; therefore, members of the same group may receive different final grades.

## Rubric

| Criteria | Points |
|---|---:|
| Service Implementation | 15 |
| Routing / routerLink | 10 |
| Reusable Components | 20 |
| Angular Binding | 15 |
| @for and @if | 10 |
| UI/UX & Mobile Adaptation | 15 |
| Demonstration & Individual Understanding | 15 |
| **TOTAL** | **100** |

## Scoring Guide

For each criterion, the following performance levels are used:

- **Full Implementation – 100% of the criterion points**
  Correct, functional, meaningful, and appropriately implemented. The requirement is clearly demonstrated.

- **Partial Implementation – 75% of the criterion points**
  Generally correct and functional, but may have minor issues, limited implementation, or areas that could still be improved.

- **Limited Implementation – 50% of the criterion points**
  Requirement is present or attempted but is incomplete, has significant issues, has limited purpose, or is poorly implemented.

- **Not Implemented / Not Demonstrated – 0%**
  Requirement is absent, cannot be demonstrated, or is non-functional to the point that it cannot be properly evaluated.

## Grade Distribution

- **Group Implementation – 85%**
  - Service
  - Routing
  - Reusable Components
  - Binding
  - `@for` / `@if`
  - UI/UX
- **Individual – 15%**
  - Demonstration and Individual Understanding

## Key Constraints Summary (for quick reference)

- Minimum 2 capstone features/modules, prototyped in Ionic-Angular.
- Static/sample data is acceptable — no real backend/API/DB connection required.
- Must include: Service, Routing (routerLink), Reusable Component(s), Angular Binding (interpolation/property/event/form), @for, @if.
- `FormsModule`/`ngModel` is optional, not mandatory.
- **No padding features just to hit a rubric line** — every requirement must serve a real, logical purpose in the prototype.
- Any group member must be able to demonstrate/explain any part of the code — grading includes individual understanding, not just group output.
